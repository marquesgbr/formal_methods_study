Source code generation is the main by-product of a B project. A B model represents a software executing sequentially. If several operations may execute in parallel, there is no more guarantee about the correctness of the software. No interruptions modifying the state variables are allowed. The model and the code are very close. This is called one-to-one translation. As a consequence, the code generated from it is also expected to run sequentially. The code, the body, is generated from the implementation. The generation is performed clause by clause. In this example, we can see that all identifiers are prefixed with the name of the machine, m0. Int is transformed into int32t type and bool is transformed in bool. 

The abstract machine is used to generate headers. In this example, the header provides the signature of the operation update_x6 and the initialization. 

Prior to code generation, an implementation has to be proved because it is useless to generate the code of a model that is possibly incorrect and it has to be implementable. It should comply with a subset of the B language called B0 where types have to be concrete and substitution has to be deterministic. Concerning B0 types, the implementable scalar types are int, or intervals of int, bool, and defined sets or enumerated sets, or intervals of defined sets. Concrete variables, inputs and outputs operation parameters, and local variables have to use implementable scalar types as well. So it can be scalar types, arrays, Cartesian product of arrays, and functions of functions. Concrete constants, in addition to types defined above, are subsets of int or of defined sets. Concrete constants and defined sets have to be valued in the closed values, using scalar, arrays, or subsets of int or of defined sets. B0 substitutions are either the sequencing of two substitutions S1 and S2, the declaration of local variables usable in X, the valuation of scalar or function, the skip substitution if-then-else, case, while loop, an operation call being operation from an imported machine scene, or local operation of the implementation. B0 expressions and predicates enable to write conditions, equalities, inequalities. It's impossible to use FOFIX, addition, division, multiplication, subtraction in a condition. We must use a local variable and calculate prior to test. Implementable expressions are identifier or literal constants, access to an element of an array, addition, subtraction, negation, multiplication and division, Boolean conditions and array initialization. In an implementation, specific lemmas are generated to ensure that the B0 code is well defined. For example, for addition, subtraction, multiplication, the results should be of the same type. For the division, the denominator should be different from zero. And for f , f should be a function and x belongs to the domain of f. 

Basic machines are specific B components. Their role is either to provide an interface with software not developed with B, by calling third-party libraries or using low-level input/output services, or to provide values for types and constants outside the generic B model. The abstract machine defines the variables implemented and the operations made available. There is no refinement, the implementation is provided as source code by the developer. There is no formal guarantee that the source code of a BASIC machine is correct. It should be tested against its formal specification by using traditional testing means. To avoid errors in basic machines, follow these two advices. First, write a trivial implementation with skip substitution, for example, then generate the skeleton of the implementation with the code generator, and finally complete the skeleton manually. And only declare concrete data in the basic machine in order to ease code association. In this example, we are going to create a basic machine, generate code, and complete the skeleton.
