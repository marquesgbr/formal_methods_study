A B project is not made of a single specification and implementation containing the whole software because all the complexity should be handled at the same time leading to the inability to prove the software. Rather, the functional decomposition of the software is performed over several components. Because the impossibility for one operation to call another one from the same component, the exception of the local operations that will be addressed later. 

In our example, M0 declares two operations, F1 and F2. In the implementation, it's not possible for F1 to call F2 and for F2 to call F1. 

So, a B project contains a collection of models linked with the two main structuring mechanisms: imports and abstract machines and sees and abstract machines. The modularity allows to manage software complexity by breaking down large software into smaller parts and to ease the proof of the models with the smaller and simpler proof obligations. It's the principles of divide and conquer. An implementation imports other abstract machines in order to implement data and operations with the lower level machines. The import clause may only appear in implementation. In our example, the implementation M0Y imports both N0 and P0. F2 and F3 may also be used to initialize the variables in M0Y. The variables of an imported machine M have to be modified in the implementation by the operation of the calling machine M. In our example, F1 cannot modify the variable VV directly. Instead, the setVV operation has to be used. Variables are implemented in one and only one component. Hence, it is not possible to import machines declaring the same variables. The solution is either to create components with independent variable sets or to regroup the important components in a single one. Local operations is a feature to ease the functional decomposition by avoiding too much levels of decomposition in the project. Local operations may be defined only in implementations, and local operations may be called from the implementation's operations being global or local. Local operations are specified in the local operation clause. Their invariant is made up by the typing of the concrete variables and they are implemented in the operation clause like global operations.
